# ringi — Go × DDD 学習用サンプル

Go でドメイン駆動設計(DDD)を実践するための学習用サンプルコードです。
「申請・承認」という小さなドメインを題材に、**パッケージ構成でレイヤードアーキテクチャを表現する**ことを目指しています。

Qiita 連載のコード置き場です。設計判断の背景や解説は記事をご覧ください。

- 第1回:GoでDDDを始めたら最初にぶつかった「クラスがない」問題と、パッケージ構成という答え(記事URLは公開後に追記)

## 動かし方

```bash
git clone https://github.com/shinchi-pmtech/ringi.git
cd ringi
go run .
```

「申請 → 提出 → 自己承認(エラー)→ 別人が承認(成功)」というデモが動きます。

```
自己承認: 自分の申請を自分で承認することはできません
承認成功。状態: approved
```

動作確認済み環境:Go 1.22

## パッケージ構成

```
.
├── domain
│   └── application          # 「申請」集約(エンティティ・値オブジェクト・リポジトリのinterface)
├── usecase                  # 「申請する」「承認する」などのユースケース
├── infrastructure
│   └── persistence          # リポジトリの実装(インメモリ)
└── presentation
    └── handler              # HTTPハンドラ
```

依存の向きはすべて `domain` に向かいます。`domain` は標準ライブラリ以外の何にも依存しません。

## 設計のポイント

- **ビジネスルールは domain のメソッドに置く** — 「承認者は申請者と同一人物であってはならない」は `Application.Approve()` の中にあります
- **interface は使う側(domain)に定義する** — Go の慣習に従うことで、依存性逆転が自然に実現します
- **フィールドは非公開** — 状態変更の唯一の手段をメソッドに限定し、不変条件をコンパイラに守らせます
