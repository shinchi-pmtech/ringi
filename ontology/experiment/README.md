# ontology/experiment

連載第1回で使った実験コードです。ユビキタス言語として合意していた文章をそのままAIに渡し、
返ってきたGoの実装を観察します。

## 実験の設計

`domainDoc` に条件ごとの一文を足して、それぞれ5回ずつ流します。

| 条件 | 足した一文 |
|---|---|
| baseline | なし（対照） |
| b-word | 差戻された申請は、修正して再提出できる。 |
| c-transition | 差戻しの状態から、申請中の状態に戻ることがある。 |

c-transition は、遷移だけを足して語には触れない条件です。「再提出」という語を
あえて使わないことで、状態の名前が変わるかどうかを見ます。

## 実行

```sh
export ANTHROPIC_API_KEY=...   # PowerShell は $env:ANTHROPIC_API_KEY = "..."
go run .
```

`out/<条件名>/` に、渡したプロンプト（`prompt.txt`）と各回の出力
（`run-01.go.txt` 〜 `run-05.go.txt`）が保存されます。

`out/first-run/` は、条件を分ける前に最初に流した5回ぶんです。プロンプトは baseline と
同じものです。記事で「合わせて10回」と書いているのは、この5回と baseline の5回を指します。

## 記事執筆時の結果

`out/` に置いてあるのは、記事を書いた時点の出力です。要点は3つです。

- baseline は5回とも差戻しを終端にした。最初に流した5回と合わせて10回、例外なし
- b-word と c-transition では10回すべてで差戻しから申請中に戻る遷移が実装された
- ただし15回すべてで、状態の名前は `Rejected` のままだった

生成結果なので、同じプロンプトでも実行時期やモデルによって変わります。
再現しない場合があることを前提に読んでください。
